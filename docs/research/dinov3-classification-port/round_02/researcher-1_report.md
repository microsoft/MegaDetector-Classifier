## **Loader requirement**

The PORT PLAN needs one `_extract_state_dict(checkpoint)` that recognizes three literal checkpoint flavours before model loading:

1. **MD-Classifier own Lightning flavour**: top-level `state_dict` exists and contains keys starting with `net.`. Use `checkpoint["state_dict"]`; normalize the leading `net.` prefix according to the target `DINOv3Classifier` module layout from prior-art P5.
2. **SINCHI RAW flavour**: top-level `model_state_dict` exists; `classifier.weight` and `classifier.bias` exist; backbone keys start with `backbone.` and do **not** start with `backbone.base_model.model.`. Instantiate the HF backbone from `checkpoint["config"]["model"]["name"]`, infer `num_classes` from `checkpoint["config"]["model"]["num_classes"]` or `classifier.weight.shape[0]`, then load the state dict directly into a wrapper whose members are `backbone` and `classifier`.
3. **SINCHI PEFT flavour**: top-level `model_state_dict` exists; `classifier.weight` and `classifier.bias` exist; backbone keys start with `backbone.base_model.model.` and LoRA adapter keys contain `.lora_A.default.weight` / `.lora_B.default.weight`. Instantiate the HF backbone from embedded `config.model.name`, wrap it with PEFT using embedded `config.peft` (`method`, `r`, `lora_alpha`, `target_modules`, plus dropout/init fields when present), then load the state dict into a wrapper whose PEFT-wrapped member produces the same `backbone.base_model.model.*` keys.

For both SINCHI flavours, the checkpoint itself supplies the model family (`config.model.name`), class count (`config.model.num_classes` = 36), image size (`config.data.image_size` = 518), and PEFT metadata when applicable. The loader should not hardcode H+, 7B, or 36 except as validation fallbacks with explicit errors.
