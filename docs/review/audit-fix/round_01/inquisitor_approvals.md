## Reviewer verdicts

ITEM-REV-001 | APPROVED — Fixes a CONFIRMED real bug. `scripts/train_dinov3.py:126` saves `DINOv3LinearProbe.export_classifier_only()`, which emits metadata at TOP LEVEL (`format, version, model_name, model_size, embedding_dim, num_classes, image_size, feature_type="cls", class_names, classifier.weight/bias`) with NO nested `meta` block and NO `transform`/`transform_version` keys. The current flavour-D detector (base_classifier.py:94-98) requires `isinstance(ckpt.get("meta"), dict)`, so the port's own stage-2 output is rejected and falls through to `ValueError("Unrecognised checkpoint format")`. Normalizing top-level metadata into `meta` and keying flavour-D on `format=="dinov3_classifier_only"` matches the §6 authoritative code-block schema (which is top-level) and the actual exporter; "transform metadata when present" correctly tolerates the exporter's omission. Constraint for the editor: keep accepting the existing nested-`meta` md_cls layout (flavour A is checked first and returns early) and do NOT mis-detect B/C — top-level `classifier.weight/bias` are absent in SINCHI RAW/PEFT (their classifier tensors live inside `model_state_dict`), so no collision. Requiring `feature_type=="cls"` is safe (only the exporter produces flavour D and it hardcodes "cls") and aligns with §10.

ITEM-REV-002 | MODIFY: make the new metadata checks CONDITIONAL (field-present OR explicit expected-* arg), never unconditional asserts on `meta` — Rationale: §6 demands the requested model_size/model_name match the checkpoint and num_classes==classifier.weight.shape[0], and adding expected-* args for the Amazon path is correct. BUT the real on-disk §2.4 checkpoints (SINCHI RAW=flavour B, PEFT=flavour C) flow through `_base_meta`, which only carries `{model_name, num_classes, image_size, peft, flavor}` — they have NO `model_size`, `embedding_dim`, `feature_type`, `transform`, `transform_version`, or `class_names`. If validation unconditionally requires those fields it will reject the team's real trained heads (exactly the over-tightening §2.4 warns against). Approve the intent provided: model_name/num_classes/image_size checks stay tolerant (present-or-shape-derived), and model_size/embedding_dim/feature_type/transform-name/version/class-order checks fire ONLY when the field is present in meta (flavour D) or a matching expected-* argument was passed by the caller. embedding_dim and num_classes may always be cross-checked against `classifier.weight` shape (always available) — that is safe and encouraged.

ITEM-REV-003 | APPROVED — Validating tensor presence + rank + shape for `classifier.weight (num_classes, hidden_size)` and `classifier.bias (num_classes,)` before `load_state_dict`, and wrapping load failures with flavour/model context, is defensive and only affects the failure path. The current code blindly indexes `cls_w.shape[1]` (IndexError on rank<2) and never checks bias; both real flavours (B/C per §2.4) and flavour D carry classifier.bias, so requiring it does not reject any real layout. Satisfies §6 "Mismatch → explicit ValueError." strict=False stays for classifier_only, strict=True for B/C — unchanged.

ITEM-REV-004 | APPROVED — Confirmed real bug: §2.4 SINCHI PEFT config uses `alpha` (r=8, alpha=8), but `LoraConfig(**peft_kwargs)` expects `lora_alpha` → the current `_wrap_peft_backbone` would raise `TypeError: unexpected keyword 'alpha'` on a genuine PEFT-H+ checkpoint. Accepting `alpha` as an alias for `lora_alpha`, rejecting non-lora `method`, and requiring r/lora_alpha/target_modules with an actionable ValueError is correct. Editor note: prefer an existing `lora_alpha` if both are present (forward-compat), and keep this behind the existing `peft` ImportError guard (§11 flavour-C gating).

ITEM-REV-005 | APPROVED — §10/§2.5 mandate CLS = `last_hidden_state[:,0,:]` (token 0). The current `_cls_embedding_from_output` silently falls back to `pooler_output` (a DIFFERENT representation) and to a 2-D payload, which would yield non-parity embeddings without warning. Restricting to a 3-D last-hidden-state (direct, or inside tuple/list/dict) and raising TypeError otherwise makes `get_embeddings` consistent with `forward()` (line 82) and preserves SINCHI parity. The real HF DINOv3 backbone always exposes `last_hidden_state`, so no working path regresses.

ITEM-REV-006 | APPROVED — §8 defines `extract_embeddings` as an embedding-ONLY wrapper, but it currently routes through `batch_image_classification_with_embeddings`, which requires a `classifier` and computes logits (`_embeddings_and_logits`, line 281). An eval()/inference_mode() embedding-only loop calling just `get_embeddings()` is the correct fix. Editor constraint (verified): the saved-name fix must reuse the CANONICAL `src.datasets.dinov3_embedding.safe_name` (which replaces ONLY `/` and `\`), so files round-trip with `DINOv3EmbeddingDataset` and `scripts/extract_embeddings.py`. The current `_embedding_pickle_path` both adds an `:`-strip AND a sha1 `.{digest}.pkl` suffix — BOTH must go, not just the hash; otherwise paths containing `:` still won't round-trip. The collision strategy (explicit error or manifest) should match whatever is later applied to extract_embeddings.py (see Cross-file notes, C1).

ITEM-REV-007 | APPROVED — Real device bug: `__init__` records `self.device` but never moves `self.net`; `DINOv3BaseInference(net=cpu_net, device="cuda")` then sends inputs `.to(self.device)` (lines 223/269/335) to CUDA while the model stays on CPU → RuntimeError. Normalizing `self.device` and moving `self.net`/`self.predictor` in `__init__` is correct; default `device="cpu"` makes it a no-op for the existing path (no invariant impact, new class). Editor note: verify subclass init ordering (DINOv3CustomWeights / DINOv3AmazonRainforest both call `super().__init__()` then `self.to(device)`) so the net isn't moved before it's built and isn't double-moved.

ITEM-REV-008 | APPROVED — Sound per §7. Resolving aliases at entry via `resolve_model_id` lets `ensure_model_available("base")` work ("all sizes callable", §7 line 184) while remaining a no-op for full repo ids ("/" passthrough); raising the existing ValueError BEFORE any Hub call gives fast actionable failure for bad sizes; normalizing snapshot/cache return paths fixes the inconsistency between the `try_to_load_from_cache` branch (returns config.json's parent) and `snapshot_download` (returns snapshot root); and the local-only check that currently reports success when ONLY `config.json` is cached (no weights/preprocessor) is a genuine bug that yields a false "available" then a downstream load failure. `huggingface_hub` stays lazily imported, so §11/§12 import invariants are preserved.

ITEM-REV-009 | APPROVED (with caveat) — Manifest-field validation, SHA256 verification for populated entries, download/local-path resolution, and passing expected dim/num_classes/class-order into `DINOv3CustomWeights` align with §7/§8, and embedding_dim/num_classes can be checked safely against `classifier.weight` shape. Caveats the editor MUST honor: (1) placeholder `None` head_url/sha256 entries must keep raising the actionable "not yet published" error (current lines 86-93) rather than crashing manifest-field validation; (2) the ONLY currently-usable path is `DINOv3AmazonRainforest(weights=<local SINCHI .pt>)` loading a flavour-B RAW head — manifest SHA verification must be skipped when sha256 is None / weights is a user-supplied local path, and class-ORDER / feature_type validation must inherit REV-002's conditional guard (fire only when the checkpoint meta actually carries `class_names`/`feature_type`, i.e. flavour D), so a local RAW head without those meta fields is not rejected.

ITEM-REV-010 | APPROVED — §10 explicitly assigns RGB conversion to the transform. Adding `convert("RGB")` (and array→PIL coercion) inside `__call__` before Resize/ToTensor/Normalize makes direct public use on L/RGBA inputs produce a `(3,518,518)` tensor instead of a normalize shape error, and is a no-op for the existing callers (base_classifier / extract_embeddings already pass RGB). Crucially it leaves interpolation (BICUBIC), size (518), and ImageNet mean/std untouched, so SINCHI parity is fully preserved.
